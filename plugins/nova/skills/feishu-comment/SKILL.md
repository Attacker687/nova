# feishu-comment：按评论收敛飞书文档

一轮收敛 = 读全文和所有未解决评论 → 逐条归类处置 → 按块写回 → 回读核对 → 标已解决 → 报告。
**正文只保留最终方案**，评审过程（方案并列、「据评论修改」注记、被否掉的草案）不进正文；需要用户拍板的事集中在文档末尾的「待决策」表，这张表是用户看待办的唯一入口。

飞书命令写法和坑以 `../../references/lark-cli.md` 为准，第一次调用 lark-cli 前先读它。

## 1. 锁定文档

- 用户给了链接就用它；没给就从当前会话里找明确提到的飞书文档，找到多个或拿不准时问用户。
- `lark-cli docs +fetch --as user --doc 【链接】 --scope outline` 读回标题，告诉用户「正在处理《标题》」。

## 2. 读取

在一个临时目录（如 `./.nova-tmp/comment/`）里落三份文件，后面都从文件读：

| 文件 | 命令 | 用途 |
|---|---|---|
| `doc.md` | `docs +fetch --doc-format markdown -q '.data.document.content'` | 读懂内容 |
| `doc.xml` | `docs +fetch --detail with-ids -q '.data.document.content'` | 块 ID、画板、表格结构 |
| `comments.json` | `drive +list-comments --url 【链接】 --solved-status false` | 未解决评论 |

同时记下 `revision_id`（写回前要比对）。文档或评论很多时分段读文件，每条评论都要读到。

## 3. 逐条归类

每条未解决评论（连同它的回复串和 `quote` 划词原文）归进下面一类：

| 类 | 判断 | 处置 |
|---|---|---|
| **改** | 给了明确的修改方向，没有需要用户选的选项，回复串里没有分歧 | 改正文 |
| **定** | 涉及取舍、多个方案可选、新的设计点，或评论串里有分歧 | 记进「待决策」表，附选项和你的建议 |
| **答** | 在提问或要求澄清 | 答案能从文档和上下文确定的，把正文改清楚；确定不了的按「定」处理 |
| **过期** | 划词原文已不在文档里，或要求的改动正文已经有了 | 不改，只标已解决 |

拿不准是「改」还是「定」时归「定」：替用户做了业务或设计决定的代价，比多问一次大。

另外检查「待决策」表：状态写成「已定：…」的行，按用户的结论改正文，状态改为「已落实」。

## 4. 改正文

- **一处改，处处改**：每改一个规则、名称、数字，在全文搜同一个概念的其他出现处，一起改到一致。
- **名称可查证**：写进正文的工具、接口、函数、字段、文件名，要么是公认的，要么在本文档或项目里有定义；查证不了又必须写的，就地标「待核实」。
- 占位符用全角【】，保持文档原有的章节结构和标题编号风格。
- 评论要求改图时：从 `doc.xml` 取该画板块的 `id` 和 mermaid 源码，改好源码后按 feishu-diagram 第 4 节换掉这个画板块。没有源码的画板无法自动改，在报告里列给用户手动处理。

### 「待决策」表

放在文档末尾（有「变更记录」一类的收尾章节时放在它前面），标题「待决策」，级别与文档一级标题相同。用 XML 的 `<table>` 写（格式见 `lark-cli skills read lark-doc/references/lark-doc-xml.md`），六列：

| 编号 | 要决定的事 | 选项 | 建议 | 状态 | 来源 |
|---|---|---|---|---|---|
| D-001 | 一句话说清问题 | A：… / B：… | 推荐哪个及理由 | 待定 | 评论人 + 划词原文前 20 字 |

编号接着表里已有的最大号往下排；已有的行只改「状态」列，其余保持原样。用户拍板的方式是把状态改成「已定：【结论】」。

## 5. 写回

1. 重新读 `revision_id`，和第 2 步记的不一致就停下，告诉用户文档刚被别人改过，重新从第 2 步开始。
2. 按块改：短句用 `str_replace`（`--pattern` 在全文唯一），段落和章节用 `block_replace`，新增内容用 `block_insert_after`。画板所在的块原样不动。
3. 只有在文档里没有画板、而且改动遍及全文时才考虑 `overwrite`，并且先征得用户同意。
4. 写入的内容含画板时，检查返回的 `.data.warnings` 有没有 `2107`，有就原样重试，最多 3 次。

## 6. 回读核对

重新 `docs +fetch --detail full`，逐项确认：

- 每条「改」「答」评论要求的改动都在正文里；
- 标题数量没有意外减少，画板数量没有减少；
- 「待决策」表是完整的表格，新增行都在表内；
- 相邻章节没有被吞掉或重复。

有不符就修正后再核一次，全部符合才进入下一步。

## 7. 标已解决

对第 3 步处理过的每条评论（四类都算）执行 `drive +resolve-comment`。条数多时在一条命令里用循环依次执行，失败的单独重试。「定」类评论也标已解决，因为它已经进了「待决策」表。

## 8. 报告

```text
【评论收敛】《标题》 链接
本轮处理 N 条评论：改 a · 定 b · 答 c · 过期 d
落实已拍板决策 e 项
待你拍板 k 项 → 见文档「待决策」表 D-00x ~ D-00y
需要手动处理：…（没有就省略这行）
```

`k = 0` 且没有未解决评论时，结论写「已收敛」。

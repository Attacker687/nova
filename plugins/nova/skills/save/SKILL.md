# save：保存工作进度

开始前先读 [运行环境约定](../../references/runtime.md)，按当前宿主处理路径、命令和子 agent。

交接单是写给**下一个接手的人**的：他没有这次会话的任何记忆，只凭交接单和仓库就要能接着干。每一段都按这个标准写。

下文的 `scripts/…` 指本 skill 目录下的脚本，调用时写成绝对路径；命令在项目仓库根目录运行。

## 1. 采集现状

在项目仓库里运行 `python scripts/handoff.py init "【标题】"`。标题用用户给的；没给就用 3～6 个词概括正在做的事。输出的 JSON 里有交接单路径、分支、提交、未提交的文件、远端名，以及远端是否已有 `nova-handoff` 分支。

不在 git 仓库里时，交接单改写到 `~/.nova/handoff/【项目目录名】/【时间戳】-【标题】.md`，跳过第 4 步。

## 2. 沉淀长期经验

这次会话里有长期价值的东西，按当前环境的 memory 规则写进 memory：用户的纠正和偏好、踩过的坑及原因、项目里不写在代码中的约定。只记下次还用得上的；进度本身写在交接单里，不进 memory。

## 3. 写交接单

写到第 1 步给出的 `path`：

```markdown
---
title: 【标题】
saved_at: 【saved_at】
machine: 【machine】
branch: 【branch】
commit: 【commit】
---

## 在做什么
一两句话：目标是什么，做到哪了。

## 已经定下的
关键决定及理由，接手的人不该再推翻或重新讨论的。

## 下一步
按顺序编号，第一条要具体到打开哪个文件、运行什么命令、看什么结果。

## 注意
坑、试过没用的办法、还没解决的问题、在等谁的答复。

## 相关文件和链接
本次改过或要看的文件（相对仓库根的路径）、飞书文档链接、写过的 memory 文件路径。

## 未提交的改动
第 1 步 dirty_files 里的文件和各自改到什么程度；没有就写「无」。
```

## 4. 发布到 nova-handoff 分支

- **有未提交的改动**：先告诉用户这些改动不会随交接单去另一台机器，问要不要先提交并推送。用户要提交，就按他的意思提交后再继续。
- **远端还没有 `nova-handoff` 分支**：先向用户确认「会在远端 【remote】 上新建 nova-handoff 分支存放交接单」，同意后再发布。
- 发布：`python scripts/handoff.py publish 【path】`。项目没有远端时加 `--no-push`，交接单只提交到本机的 nova-handoff 分支。

## 5. 报告

告诉用户：交接单路径、是否已推送到远端（分支名、提交号）、下一步的第一条；提醒可以打开新会话（Claude Code 也可 `/clear`），说「用 nova 恢复进度」即可接上。

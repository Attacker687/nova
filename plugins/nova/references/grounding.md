# 有据可查：nova 所有 agent 的共同规则

nova 的产物（代码地图、方案、评审意见、测试方案）会被下一个 agent 当成事实继续用，一处编造会一路放大。所以每句关于现状的话都要有出处。

1. **先查后说**：提到任何文件、类、函数、接口、表、字段、配置项之前，用 Read / Grep / Glob 确认它存在。
2. **注明出处**：关于现有代码的陈述带 `路径:行号`（路径相对代码根，区间写 `路径:起-止`），关于需求和文档的陈述带文件名和章节，或 ≤2 行的原文引用。给不出出处的，就不作为事实陈述。
3. **不知道就标出来**：查不到、拿不准的，写「待确认：【具体问题】」，不去猜一个看起来合理的名字。
4. **发现错了立刻改**：前面的判断被证据推翻，直接改掉，并在交付说明里写一句改了什么。
5. **先找现成的**：打算新建类、表、接口、模块之前，先搜代码里有没有能复用或扩展的，并写明搜了什么、结论是什么。
6. **交付前自查**：交付前把自己写下的出处抽查几处（至少 5 处，不足 5 处就全查），确认路径和行号对得上。

# restore：恢复工作进度

开始前先读 [运行环境约定](../../references/runtime.md)，按当前宿主处理路径、命令和子 agent。

交接单由 save 写入本机的 `.nova/handoff/` 和项目 git 的 `nova-handoff` 分支。下文的 `handoff.py` 指 `【本 skill 目录】/../save/scripts/handoff.py`，调用时写成绝对路径；命令在项目仓库根目录运行。

## 1. 找交接单

运行 `python handoff.py list`（会先从远端取最新的 nova-handoff 分支）。输出按时间从新到旧排，每项有标题、保存时间、机器、分支。

- 最新一份的分支就是当前分支，或者用户指明了要哪份：直接用它。
- 否则把最近几份列给用户选。
- 一份都没有：说明没有找到交接单，结束。

不在 git 仓库里时，到 `~/.nova/handoff/【项目目录名】/` 下找最新的文件。

## 2. 读交接单

本机有文件（`local` 字段）就直接读；只在分支上的，先
`python handoff.py show 【name】 --out .nova/handoff/【name】`，再读这个文件。

## 3. 对齐代码

对比交接单里的 `branch`、`commit` 和当前状态：

- **分支不同**：告诉用户，问是否切到交接单的分支。当前有未提交改动时先问用户怎么处理，处理完再切。
- **本机没有那个提交**（`git cat-file -e 【commit】` 失败）：`git fetch` 后再查；仍然没有，说明保存时的提交没推送，告诉用户。
- **当前分支落后于该提交**：`git pull --ff-only`。

「未提交的改动」一节列了文件时，提醒用户这些改动还留在保存进度的那台机器上。

## 4. 补上下文

读交接单「相关文件和链接」里列出的 memory 文件和关键文件，读到能开始第一步为止。

## 5. 呈现并接手

向用户简述：在做什么、已经定下的、下一步清单，以及第 3 步发现的差异。然后从「下一步」的第一条开始做；用户只是想看看进度的，就停在这里等他发话。

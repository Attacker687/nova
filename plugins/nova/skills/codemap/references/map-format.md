# 代码地图格式

代码地图写给**之后来改这份代码的 AI 和人**：读完它，应该知道去哪找什么、改一处会牵动哪里、有哪些不成文的规矩。它描述现状，不评价好坏、不提改进建议。

## 目录

```text
docs/codemap/【程序】/
├── README.md          总览（入口）
├── 01-modules.md      模块
├── 02-entrypoints.md  入口
├── 03-data.md         数据
├── 04-flows.md        关键流程
├── 05-rules.md        业务规则
├── 06-conventions.md  约定与坑
└── _meta.json         扫描记录（skill 写，不用手改）
```

某一篇超过约 800 行时，拆成「索引文件 + 同名文件夹」：如 `02-entrypoints.md` 只留目录，内容按模块放进 `02-entrypoints/【模块】.md`。

## 各篇内容

所有关于代码的陈述带 `路径:行号`，路径相对代码根（`_meta.json` 的 `root`）。

### README.md
- 一句话：这个程序是做什么的，服务谁。
- 技术栈：语言、框架、主要依赖（附依赖声明文件出处）。
- 怎么跑：构建、启动、跑测试的命令，每条注明从哪看来的（构建文件、脚本、README、CI 配置）；查不到的写「待确认」。
- 目录结构：前两层目录各一句说明。
- 模块一览：每个模块一行，链接到 01。
- 建议阅读顺序：新人想改功能，先看哪几个文件。

### 01-modules.md
每个模块一节：职责（一两句）、关键文件（3～8 个，各一句说明）、依赖了哪些模块和外部系统、被哪些模块依赖。

### 02-entrypoints.md
按类型分表，每行一个入口：

| 类型 | 表格列 |
|---|---|
| HTTP 接口 | 方法、路径、处理函数（`路径:行号`）、一句话说明 |
| 页面路由 | 路径、页面组件、一句话说明 |
| 调用的后端接口（前端） | 方法、路径、调用处、所属页面或功能 |
| 定时任务 / 消息消费 | 触发方式、处理函数、一句话说明 |
| 命令行 / main | 入口、参数要点 |

### 03-data.md
- 数据实体：表、实体类、主要 DTO；每个写定义位置、关键字段、与其他实体的关系。有 DDL 或迁移脚本的注明出处。
- 外部存储和中间件：数据库、缓存、消息队列、对象存储，各在哪配置、在哪使用。
- 关键配置项：会影响行为的配置键、默认值、在哪读取。

### 04-flows.md
3～8 条最重要的业务流程。每条：
- 触发入口；
- 按顺序的步骤，每步一行，带 `路径:行号`，直到落库、返回或发消息；
- 一张 mermaid 图（`sequenceDiagram` 或 `flowchart TD`）。

### 05-rules.md
代码里实现的业务规则（校验、状态流转、计算公式、权限判断、限额、默认值）。每条一行：

| 编号 | 规则（一句话，业务语言） | 出处 | 原文（≤2 行代码） |
|---|---|---|---|
| R-001 | 订单金额为 0 时不允许提交 | `order/OrderService.java:88` | `if (amount <= 0) throw …` |

这份清单是写测试方案的依据，宁可多列，不要漏。

### 06-conventions.md
分层方式、命名习惯、错误处理、日志、事务、配置读取、测试的组织方式和常用写法；以及读代码时发现的坑（隐式约定、容易改错的地方）。每条附一个出处作例子。

## _meta.json

```json
{"program": "…", "root": "代码根的绝对路径", "commit": "扫描时的提交", "generated_at": "…",
 "mode": "full | update", "batches": 0, "source_files": 0}
```

## 扫描笔记（多批扫描时的中间产物）

每批一份 `【批次号】.md`，放在派单指定的目录，结构和上面 01～06 相同（只写本批看到的），每条都带出处。末尾加一节「跨批线索」：本批看到的、指向其他模块的调用和依赖，方便合成时拼起来。
